## V1 scope — locked decisions (from `claude/v1-escopo-decisoes.md`)

- **Single user, no auth.** No login screen, no accounts. If publicly deployed, just an env-var password gate.
- **Platform**: responsive web app (mobile-friendly), **not** an installable PWA, **not** native. Deploy to Vercel — not local-only.
- **SQL execution**: DuckDB-WASM, client-side in the browser. No server-side sandbox.
- **Operational DB**: Postgres, holds user progress + exercise index/metadata only. Exercise datasets themselves live in DuckDB-WASM, not Postgres.
- **Four session modes only**: Metric Lab, Granularity Trainer, Query Architecture (full version, not the puzzle), SQL Build. Everything else from the PRD (Daily Drill, Rapid Fire, Investigation Budget, Scenario, all Debugger modes, Validation Lab, Confidence Calibration, Workout Mode, Boss Fight, Adaptive Practice, Autonomy/Calibration Score) is explicitly out of V1.
- **No hint system at all in V1** — simplifies feedback logic; every correct answer counts as unaided by definition.
- **65 exercises**, 3 domains (e-commerce, SaaS, fintech), difficulty **L3–L10** (L1/L2 skipped as too basic).
- **Exercise generation is an offline script**, not a live in-product feature — must validate every generated exercise by actually running its reference SQL against the dataset before it's admitted.
- **Leveling**: one-time placement test (12–16 questions, ~L4/L5) sets per-mode starting level. Level is tracked **per mode** (4 independent levels), advances after 2 unaided correct answers in a row, never auto-regresses on a miss.
- **Gamification**: simple streak + per-skill progress dashboard only.

## Build order (per `claude/v1-escopo-decisoes.md` §9) and current status

1. ✅ Project scaffold — Next.js (App Router) + TypeScript + Tailwind, `src/` dir, `@/*` import alias, npm.
2. ✅ Operational DB schema (per-mode progress, exercise index) — Postgres via Drizzle ORM, hosted on Vercel Postgres/Neon (see `docs/adr/0003-drizzle-and-vercel-postgres.md`). Schema in `src/db/schema.ts`, migrations in `src/db/migrations/`, contract tests in `src/db/__tests__/`.
3. ✅ Exercise generation + validation script — **65/65 exercises admitted** (`content/exercises/validated/`, tracked in `content/exercises/generation-log.json`), covering all 3 domains × 4 modes, L3–L10. Authoring format in `scripts/exercises/exercise-schema.ts`, validator that actually runs each exercise's referenceSql against its real dataset in `scripts/exercises/validate.ts`, admission CLI is `npm run exercises:admit`. Generation itself stays manual by design (paste `content/exercises/GENERATION_PROMPT.md` into a Cowork session → save batch → admit) — no live in-product generation, per the V1 scope doc.
4. ✅ Synthetic datasets for the 3 domains — Parquet files generated by `scripts/datasets/` into `content/datasets/<domain>/`, deterministic/seeded, referential integrity tested. This step is the *data*; wiring DuckDB-WASM to read it in the browser is part of step 6 (the shared SQL runner), not this step.
5. ✅ Placement test — session lifecycle (`src/lib/sessions.ts`), server-side grading against `referenceSql` without ever exposing it to the client (`src/lib/server-grading.ts`, see `docs/adr/0005-grading-runs-server-side-against-reference-sql.md`), API routes (`/api/placement/start`, `/api/placement/submit`, `/api/exercises/[id]/grade`), and the UI (`src/app/placement/page.tsx`). Verified end-to-end via real HTTP calls against a seeded dev DB.
6. ⬜ The 4 session modes with granular feedback
7. ⬜ Streak + skill dashboard
8. ⬜ Deploy to Vercel with password gate

## Working conventions for this project

- Preserve **"Concept first, query second"** in every mode: never let a UI skip to a SQL editor before population/grain/metric are established.
- Feedback must always be granular (per-step checklist), never a bare "Wrong."
- This is a from-scratch build with no legacy constraints — follow the global TDD/lint/docs conventions in `~/.claude/CLAUDE.md`, adapted to the Next.js/TypeScript stack here (that file's Python-specific snippets, e.g. `pyproject.toml`, don't apply to this project; use `vitest`/`jest` + `eslint` equivalents instead).
- Commands: `npm run dev` (dev server), `npm run build`, `npm run lint`.
